# Summary v1.1

Дата: 2026-02-16

## Цель
Заменить TeleWow локальным сервисом для Avito, который отвечает только по недвижимости, молчит в нецелевых категориях и отправляет лиды в Telegram.

## Зафиксированные правила
1. Первая версия работает только по недвижимости.
2. Авто/другие категории: полный игнор без ответа клиенту.
3. Режим боевой: автоотправка ответов в Avito без согласования.
4. Лид только при наличии контакта (телефон/мессенджер).
5. Лид уходит в отдельный Telegram-чат: summary + контакт + контекст.
6. Роутинг учитывает контекст объявления и текст диалога.

## KPI MVP
1. 0 автоответов в нецелевых категориях.
2. Доля диалогов с извлеченным контактом.
3. Время до первого ответа.
4. Доля технических ошибок по интеграциям.

## Scope MVP
1. Avito + OpenAI + Telegram.
2. Категория `REAL_ESTATE`.
3. Логи, аудит, базовая админ-панель.

## Out of Scope
1. Ответы по авто/прочим категориям.
2. Полная CRM-интерфейсная часть.
3. Реализация интеграций Юла/Яндекс.Недвижимость.

## Текущий статус интеграций (обновлено 2026-02-16)
1. Avito OAuth: работает.
2. Avito polling (`/messenger/v2/.../chats`): работает.
3. Avito send message (`/messenger/v1/.../messages`): работает с payload `type=text + message.text`.
4. Telegram leads: работает при корректном `TELEGRAM_LEADS_CHAT_ID` и доступе бота к чату.
5. Burst ingestion: включена догрузка истории (`v3/messages`) с fallback на `v1/messages` для чатов, где `v3` отдает `402/404/405`.
6. Для инцидентов доступна диагностика чата через API/CLI (`/api/chats/external/{external_chat_id}/diagnostics`, `make chat-diagnostics`).
7. Self-learning v1 включен:
   - автозапуск при работающем poller раз в `SELF_LEARNING_INTERVAL_HOURS`;
   - команда запуска цикла: `make learn-once`;
   - статус: `make learning-status` или `GET /api/learning/status`;
   - создаются версии обучающих примеров;
   - в ответы подмешиваются релевантные примеры по canary-схеме.
8. Подготовлен путь переноса на Jino VPS:
   - пошаговый гайд `docs/DEPLOY_JINO.md`;
   - скрипт миграции `scripts/migrate_sqlite_to_postgres.py`.

## Обновление диалога и UX (2026-02-17)
1. В `MessageProcessor` добавлены детерминированные правила (до LLM):
   - если клиент пишет короткий бюджет (`8-12`, `8р-12р`, `812`), бот уточняет формат "тысяч рублей в месяц";
   - на "куда вам набрать" бот не выдает прямой номер менеджера и объясняет схему обратного звонка;
   - первый ответ в новом чате: мягкое приветствие + вопрос, актуален ли вопрос заселения.
2. Усилен контекст объявления в runtime-промпте:
   - бот получает `ad_title/ad_category` как обязательный контекст ответа;
   - для объявлений типа "койко-место" ответ остается в этом фокусе.
3. Telegram lead-card сделана компактнее:
   - summary сокращается;
   - в карточку попадают последние 3 реплики вместо 5.

## Обновление по weekly-отчету и диалогу (2026-02-17)
1. Анти-спам для отчетов:
   - автоотчет теперь отправляется один раз в неделю: понедельник 09:00 (`Asia/Yekaterinburg`);
   - период отчета: предыдущая календарная неделя (пн-вс);
   - отчет полностью на русском языке.
2. Релевантность отчета:
   - в weekly-отчет включаются только объявления недвижимости.
3. Коррекция поведения бота в чате:
   - если клиент уже явно пишет о заселении (наличие/даты/формат/бюджет), бот не спрашивает «актуален ли вопрос» заново;
   - бот сразу продолжает квалификацию и ведет к сбору контакта.
