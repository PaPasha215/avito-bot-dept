# ТЗ: Упрощение Telegram-меню до 2 уровней (v1)

Дата: 2026-02-18

## Цель
- Убрать перегрузку интерфейса менеджера в Telegram.
- Сократить время до целевого действия (открыть карточку, отметить статус, отправить сообщение).
- Исключить "портянки" кнопок в одном сообщении.

## Принципы UX
1. Не более 4-5 кнопок на экран.
2. Один экран = одна задача.
3. Кнопки с понятными глаголами: `Открыть`, `Статус`, `Связаться`.
4. Второстепенные действия убираются во 2 уровень.
5. Возврат на шаг назад доступен всегда.

## Информационная архитектура (2 уровня)

### Уровень 1: Список заявок
- Формат карточки в списке:
  - `#LeadID | Имя | Объект`
  - `Статус | Дата | Короткий summary`
- Кнопки (под карточкой):
  - `Открыть`
  - `Быстрый статус`

### Уровень 2: Экран одной заявки
- Блоки:
  1. Контакт клиента
  2. Объект и источник
  3. История/summary
  4. Действия
- Кнопки действий:
  - `Статус: NEW/IN_PROGRESS/WON/LOST/SPAM`
  - `Позвонить`
  - `Написать`
  - `Назад к списку`

## Что убрать из текущего интерфейса
1. Дублирующие кнопки (`Текст`, `WA`, `П...`, `Отправ...`) в каждом блоке списка.
2. Большие панели с несколькими рядами действий в одном сообщении.
3. Одновременный показ "операционных" и "финансовых" кнопок на одном экране.

## Минимальный сценарий (MVP)
1. Менеджер открывает список заявок (уровень 1).
2. Нажимает `Открыть`.
3. На уровне 2 ставит статус и выполняет 1 действие связи.
4. Возвращается в список.

## Статусы и переходы
- Доступные статусы: `NEW`, `IN_PROGRESS`, `WON`, `LOST`, `SPAM`.
- Рекомендуемые переходы:
  - `NEW -> IN_PROGRESS`
  - `IN_PROGRESS -> WON/LOST/SPAM`
- При смене статуса сохраняется `changed_at`, `changed_by`, `comment` (опционально).

## Технические требования к Telegram-боту
1. Использовать `InlineKeyboardMarkup`.
2. Нажатия кнопок обрабатывать через `callback_data` (короткий и стабильный формат).
3. Длина `callback_data` <= 64 байт.
4. Для списка использовать пагинацию:
   - `Назад`, `Вперед`, `Обновить`.
5. Обновлять существующее сообщение (`editMessageText`), а не отправлять новое при каждой операции.

## Формат callback_data (пример)
- `lead:open:<id>`
- `lead:status:<id>:NEW`
- `lead:status:<id>:IN_PROGRESS`
- `lead:status:<id>:WON`
- `lead:status:<id>:LOST`
- `lead:status:<id>:SPAM`
- `lead:list:<page>`

## KPI после внедрения
1. Время от открытия лида до первого действия < 15 секунд.
2. Доля успешной смены статуса без ошибок > 98%.
3. Снижение числа нажатий на лид минимум на 30%.

## План внедрения
1. Сделать прототип 2-уровневого меню на тестовом чате.
2. Прогнать 3-5 реальных лидов руками.
3. Проверить скорость работы и читаемость интерфейса.
4. Включить для рабочей группы.
