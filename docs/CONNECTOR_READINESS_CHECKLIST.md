# Connector Readiness Checklist (Marketplaces)

Дата: 2026-02-18

## Цель
- Подключать новые площадки в единый контур бота только после формальной проверки готовности.
- Избежать интеграций, где нет API для чатов/исходящих сообщений.

## Универсальный checklist для новой площадки
1. Есть официальный API для:
   - чтения входящих сообщений/чатов;
   - отправки исходящих сообщений;
   - получения контекста объявления (id, title, url, category).
2. Есть официальный механизм авторизации (OAuth/API key) и стабильная документация.
3. Разрешено автоматическое общение ботом по правилам площадки (ToS/политики).
4. Есть вебхуки или polling без нарушений лимитов.
5. Можно реализовать идемпотентность:
   - уникальный `event_id`/`message_id`;
   - защита от дублей исходящих сообщений.
6. Можно извлекать и сохранять:
   - `external_chat_id`, `external_message_id`, `external_ad_id`;
   - отправителя и время сообщения.
7. Можно отправлять лид в Telegram в текущем формате без потери контекста.
8. Есть тестовый контур/песочница или безопасный canary-процент.
9. Понятны SLA/ограничения (rate limits, 402/403/429 и т.д.).
10. Есть контакт техподдержки API и процесс эскалации.

## Приоритизация площадок (на сегодня)

### P1 — Avito (уже в проде)
- Статус: `READY / ACTIVE`.
- Почему: рабочая интеграция в проекте уже есть.
- Что делать: продолжать улучшать качество диалогов и конверсию в контакт.

### P2 — Циан (потенциально лучший следующий шаг)
- Статус: `CANDIDATE (требует валидации доступа)`.
- Основание:
  - в официальной публикации Циан про API для CRM указаны методы для чатов и лидов.
- Риск:
  - доступ к API может быть доступен только партнерам/агентствам.
- Решение:
  - запросить доступ и документацию в ЛК/поддержке Циан;
  - после получения docs быстро подключить через общий adapter.

### P3 — Юла
- Статус: `LIMITED (по открытым материалам упор на фиды, не на chat API)`.
- Основание:
  - в help-материалах публично описаны автозагрузка XML/YML и автоответы в интерфейсе.
- Риск:
  - нет подтвержденного открытого API для полноценного двустороннего чат-бота в нашем контуре.
- Решение:
  - использовать как канал публикации (feed) и ручные/встроенные автоответы;
  - параллельно запросить у поддержки наличие chat API.

### P4 — Яндекс.Недвижимость
- Статус: `LIMITED (feed-first)`.
- Основание:
  - официальные материалы описывают YML/XML фиды для выгрузки и загрузку через Яндекс.Вебмастер/API.
- Риск:
  - для нашего use-case нужен именно чат API; в публичных docs акцент на feed/индексацию.
- Решение:
  - использовать как витрину трафика через feed;
  - лид-менеджмент вести в существующем CRM-контуре/Telegram.

## Вывод по приоритету внедрения
1. `Сразу`: Avito (оптимизация текущего).
2. `Следующий интегратор`: Циан (если подтверждаем доступ к chat API).
3. `Параллельно как витрины`: Юла + Яндекс.Недвижимость через feed.
4. `После подтверждения API`: только тогда писать полноценный adapter для chat-bot режима.

## Что нужно от вас для запуска следующей площадки
1. Название площадки и доступ в кабинет владельца.
2. Ссылка на официальную API-документацию.
3. Тестовые ключи/OAuth и тестовый аккаунт.
4. Разрешение на auto-reply по правилам площадки.
5. Целевой чат для лидов в Telegram (тот же или отдельный).
